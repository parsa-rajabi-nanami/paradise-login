## Frontend login and OTP

- Shortcode `[PLWN_login_form]` invokes public function `PLWN_login_form()` (`inc/core.php:15-24`; template include is anchored to `__DIR__` with slash-separated path).
- `PLWN_ajax_get_csrf_token()` supplies a cache-compatible token backed by an HttpOnly SameSite cookie; `PLWN_is_same_origin_request()` validates legacy nonce requests (`inc/core.php:20-77`). `PLWN_ajax_send_sms_function()` is registered for unauthenticated action `PLWN_ajax_send_sms`; handler and nested SMS class includes use `__DIR__`-anchored slash-separated paths. POST fields: legacy `nonce`, `mobile_number`, optional `otp_code`, and `csrf_token`; nonce action `PLWN_login_form_script_nonce` (`inc/core.php:80-105`).
- AJAX response keys used by the client: `status`, `message`, `text`, optional `new_input`, `url`, and `port` (`inc/class/send-sms-user.php:23-29`; `inc/class/user-login-sing-up.php:39-67`; `assets/js/PLWN-login-form-script.js:27-43`).
- Public `PLWN_normalize_phone_number()` converts Persian and Arabic-Indic digits, strips Unicode spacing/format/dash/parenthesis characters, validates 1–15 ASCII digits, and applies filter `paradise_login_normalized_phone_number($normalized, $phone_number)` (`paradise-login-with-numbers.php:25-49`). The plugin is country-agnostic; `country_code` is only prepended for the SMS gateway.
- Public classes and callable methods: `Send_sms_user::__construct()`, `Send_sms_user::Send_Sms_Otp()` (`inc/class/send-sms-user.php:2-12`); `PLWN_Manage_User::__construct()`, `PLWN_Manage_User::PLWN_check_user()` (`inc/class/user-login-sing-up.php:3-13,257-348`).
- SMS template tokens: `%PLWN_otp%`, `%PLWN_mobile_number%` (`inc/class/send-sms-user.php:15-18`).
- Persisted user meta key `mobile_user` stores ASCII digits in the submitted 1–15 digit format; auto-created `user_login` uses the same value and new-account email is `plwn_{phone}@{default_email_domain}` (default `example.com`) (`inc/class/user-login-sing-up.php:38-59`). `paradise_login_default_user_email` filters the final email with arguments `$email, $phone`; existing users' emails are not changed and email is not used for lookup. Lookup checks exact canonical metadata first, then one `IN` query for the submitted and Persian/Arabic-Indic legacy digit variants ordered by user ID; existing metadata is never rewritten (`inc/class/user-login-sing-up.php:92-140`).
- Normalized phone values are used in send, verify, registration, lookup, and phone-keyed cooldown/rate-limit/OTP transient identities; existing ASCII canonical input remains unchanged.
- OTP transient key `PLWN_{REMOTE_ADDR}_otp_{phone}` stores `v2$<HMAC-SHA256>` for new codes and accepts an existing unprefixed plaintext transient once until its original expiry; send cooldown key `PLWN_form_submit_{REMOTE_ADDR}` remains, with an added HMAC-keyed per-phone cooldown; both send cooldown checks use serialized option locks (`inc/class/user-login-sing-up.php:271-279,288-333`; `inc/class/send-sms-user.php:50-86`).
- Added internal transient families `PLWN_otp_rate_*` for IP, phone, and per-code rate counters, with option locks `PLWN_otp_rate_lock_*` and `PLWN_otp_claim_*` for serialized updates and one-time consumption (`inc/class/user-login-sing-up.php:95-183`).
- Filters `paradise_login_otp_rate_limits($limits)` adjusts defaults for verify-IP (120), verify-phone (30), per-code attempts (5), and the rate window (900 seconds) (`inc/class/user-login-sing-up.php:95-105`); `paradise_login_otp_lifetime($lifetime, $options)` adjusts the dynamically-defaulted OTP lifetime (1–900 seconds) (`inc/admin/core-admin.php:293-310`). `paradise_login_default_user_email($email, $phone)` may override a new account email (`inc/class/user-login-sing-up.php:38-39`).
- `wp_login` action is fired after authentication; auth cookie call explicitly sets non-remembered semantics and secure-cookie state with `wp_set_auth_cookie($user->ID, false, is_ssl())` (`inc/class/user-login-sing-up.php:65-78`).
- Public AJAX action hooks are `wp_ajax_nopriv_PLWN_ajax_get_csrf_token`, `wp_ajax_nopriv_PLWN_ajax_send_sms`, and `wp_ajax_PLWN_logo_get_image`; the callbacks read request data from WordPress request globals (`inc/core.php:49,108`; `inc/admin/core-admin.php:319-320`).
- `redirect_to_login()` is hooked to `init`; consumes `redirect_login` and `url_login_page` settings and redirects unauthenticated visitors (`inc/core.php:47-83`).

## Removal behavior

- `uninstall.php` deletes the plugin settings, transient keys matching `_transient_PLWN_` and `_transient_timeout_PLWN_`, stored version option `paradise_login_with_numbers_version`, and this release's `PLWN_send_rate_lock_*`, `PLWN_otp_rate_lock_*`, and `PLWN_otp_claim_*` options. Multisite uninstall iterates each site; no global cache flush is performed (`uninstall.php:7-50`).
